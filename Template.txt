# ABSTRACT

**“AI-Powered Study Companion”** is a comprehensive web-based application designed to enhance the learning and productivity experience for students and professionals. The system integrates traditional note-taking capabilities with advanced Artificial Intelligence features to create an intelligent study environment.

Key features include:
- **Smart Note Management:** A rich-text editor for creating, organizing, and searching notes with tagging and categorization.
- **AI-Assisted Chat:** An interactive chat interface powered by OpenAI (via Groq) that maintains user context and assists with queries.
- **Flashcards System:** Tools for creating and reviewing flashcards with difficulty tracking to aid memory retention.
- **Secure Authentication:** Robust user security using JWT, bcrypt, and email verification.

The project leverages the MERN stack (MongoDB, Express.js, Node.js) with EJS for server-side rendering, ensuring a responsive and scalable architecture. By combining organizational tools with AI assistance, the system aims to streamline the study process and improve information retention.

# CHAPTER 1 – INTRODUCTION

The **AI-Powered Study Companion** is a web application developed to address the modern student's need for a unified platform that combines note-taking, organization, and intelligent assistance. In an era of information overload, efficient management of study materials is crucial. This project provides a digital solution where users can not only store information but also interact with it intelligently.

The system is built using **Node.js** and **Express.js** for the backend, ensuring high performance and scalability. **MongoDB** is employed as the database to handle flexible data structures like notes and user contexts. The frontend utilizes **EJS (Embedded JavaScript)** templates to render dynamic content directly from the server, providing a seamless user experience.

A distinguishing feature of this project is the integration of **OpenAI's Large Language Models**. This allows the application to offer context-aware chat assistance, helping users understand complex topics related to their notes. Additionally, the system includes a flashcard module for active recall and a music player for creating a focused study environment.

# CHAPTER 3 – PROBLEM DESCRIPTION

### 3.1 Existing System
Students and professionals often rely on disparate tools for their workflow: one app for taking notes, another for flashcards, and search engines or separate AI tools for research. This fragmentation leads to:
- **Context Switching:** Constant switching between applications breaks focus.
- **Disorganized Data:** Information is scattered across different platforms.
- **Lack of Integration:** Notes are static and do not interact with study tools.

### 3.2 Proposed System
The proposed **AI-Powered Study Companion** solves these issues by unifying these functionalities into a single platform.
- **Centralized Data:** Notes, flashcards, and chat history are stored in one secure database.
- **Context Awareness:** The AI assistant has access to user context, allowing for more relevant and personalized answers.
- **Productivity Tools:** Integrated features like flashcards and background music support a complete study session without leaving the app.

# CHAPTER 4 – LITERATURE SURVEY

The development of this project is grounded in established web technologies and modern AI integration patterns.

### 4.1 Node.js and Express.js
Node.js provides a non-blocking, event-driven architecture ideal for I/O-heavy applications like real-time chat and data management. Express.js serves as the web framework, simplifying routing and middleware management.

### 4.2 MongoDB and Mongoose
MongoDB, a NoSQL database, was selected for its flexibility in storing unstructured data such as rich-text notes and chat logs. Mongoose provides a schema-based solution to model this application data, ensuring data integrity and validation.

### 4.3 OpenAI API
The integration of Large Language Models (LLMs) transforms static applications into intelligent systems. This project utilizes the OpenAI API (specifically via Groq for performance) to provide natural language understanding and generation capabilities.

### 4.4 EJS (Embedded JavaScript)
EJS is used for server-side templating. It allows the generation of HTML markup with plain JavaScript, enabling the application to serve dynamic pages based on the user's state (e.g., logged in vs. logged out) directly from the backend.

# CHAPTER 6 – SOFTWARE AND HARDWARE DESIGN

### 6.1 System Architecture
The application follows the **Model-View-Controller (MVC)** architectural pattern:
- **Model:** Defines the data structure (Mongoose Schemas).
- **View:** Renders the user interface (EJS Templates).
- **Controller:** Handles the business logic and processes user requests.

### 6.2 Database Design
The database consists of the following primary collections:

1.  **Users:** Stores user profile, authentication tokens, and verification status.
2.  **Notes:** Stores note content (rich text & plain text), metadata (tags, color), and status (pinned, archived).
3.  **Cards:** Stores flashcard front/back content, difficulty level, and review stats.
4.  **ChatSessions:** Stores conversation history between the user and the AI.
5.  **UserContexts:** Stores long-term context derived from user interactions for the AI.

### 6.3 Data Flow
1.  **Client Request:** User interacts with the UI (e.g., submits a login form).
2.  **Route Handler:** Express router directs the request to the appropriate controller.
3.  **Controller Logic:** Controller validates input, interacts with the Database Model, or calls external APIs (OpenAI).
4.  **Response:** The server sends back a JSON response (for APIs) or renders an EJS page.

# CHAPTER 7 – ML MODULE

The Machine Learning component of this project is powered by the **OpenAI API**, accessed via the Groq client for optimized inference.

### 7.1 Integration
The integration is handled in `src/utils/openai.js`. The system configures the OpenAI client with an API key and base URL.

### 7.2 Chat Completion
The core function `chatCompletion` sends a series of messages to the model and retrieves the generated response.
- **Model Used:** `openai/gpt-oss-120b` (or similar configured model).
- **Temperature:** Set to `0.7` to balance creativity and accuracy.

### 7.3 Context Management
To make the AI "smart," the system implements a Context Retrieval Augmented Generation (RAG) pattern:
1.  **User Context:** Stored in the `UserContext` model.
2.  **Prompt Engineering:** System prompts (`answeringPrompt.txt`, `contextPrompt.txt`) guide the AI's behavior.
3.  **Flow:** When a user sends a message:
    - The system retrieves the stored User Context.
    - It constructs a prompt containing the System Instructions + User Context + Current Query.
    - The AI generates a response based on this enriched input.

# CHAPTER 8 – CODING

The project source code is organized into a modular directory structure:

### 8.1 Directory Structure
- **`src/`**: Contains the source code.
    - **`controllers/`**: Logic for Auth, Notes, Chat, Cards, etc.
    - **`models/`**: Mongoose schemas (`User.js`, `Note.js`, etc.).
    - **`routes/`**: API route definitions (`authRoutes.js`, `noteRoutes.js`).
    - **`utils/`**: Helper functions (`openai.js`, `mail.js`, `asyncHandler.js`).
    - **`views/`**: EJS templates for the frontend (`app.ejs`, `loginSignUp.ejs`).
    - **`middlewares/`**: Auth checks (`tokenChecker.js`) and validation.
    - **`db/`**: Database connection logic.
- **`public/`**: Static assets (CSS, Images, HTML files).
- **`index.js`**: Application entry point.

### 8.2 Key Modules
- **`index.js`**: Sets up the Express server, middleware (CORS, Cookie Parser), and connects to MongoDB.
- **`auth.js` (Controller)**: Handles user registration, login, and token generation.
- **`chat.js` (Controller)**: Manages the interaction between the user and the OpenAI API.
